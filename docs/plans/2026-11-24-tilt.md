## Spec (from the map row; binding)
- **Trends**: a "Tilt" `Section` (level 3) below Clutch; follows period, playlist and With filters.
- Two column charts: win % by **session game number** (1–3 / 4–6 / 7–9 / 10+) and **after** a win /
  1 loss / 2 losses / 3+ losses (each match in one streak bucket). Dashed line at the average, Wilson 95%
  whiskers, match count under each label.
- Game number and streak count **every played match in the session that the "everything" filter keeps**
  (`inFilter(_, "everything")`: private and offline — Training, Workshop, Custom Training, bots — left
  out, as the prototype did; user's choice 2026-11-24), whatever the page's filters. Only casual/ranked/tournament (`clutchCounts`) matches that pass the filters and
  started in the period land in buckets. A match with no result keeps its game number but is not part of
  the streak (doesn't extend or break it, gets no streak bucket).
- Streak buckets compare against the other matches that have a decided match before them; game buckets
  against all counted matches. z uses the pooled rate (as the prototype).
- **Verdict** over the four tilt buckets (7–9, 10+, 2 losses, 3+ losses):
  1. **Too few to tell yet** — under 60 counted matches, or any tilt bucket under 10 (names the thinnest).
  2. **You drop …** — worst tilt bucket at z ≤ −2.5 (names it; its rate vs the rest).
  3. **No clear sign of tilt** — every tilt bucket 60+.
  4. **No sign of tilt so far, but only N …** — otherwise (names the thinnest).
  The prototype code used `totalN < FIRM_N` (60) for state 1 while the map row and its commit body say 30;
  user's choice (2026-11-24): keep 60 as coded, and correct the map row's "under 30" to "under 60".
- Bars: grey within chance; red/green only past ±2.5 and never under 10; stripes under 60; solid outline
  on the bar a "You drop" names; bold label on the named bucket; legend for every mark shown.
- Note line: "You ended N of M sessions on a loss." + the fixed "win % can't see all tilt" text. M =
  sessions with a played match in the period (under "everything", not the page filters) that have a
  decided match, **excluding the current session** (`idx.current`); each judged by its last decided match
  over the **whole session**, even past the period end (user's choice 2026-11-24).
- Empty state as Clutch: "No casual, ranked or tournament matches here." No recap line. No nudge.

## Approach
Mirror step A's split (numbers from the server, text in web logic), but send only counts.

1. **`src/shared/tilt.ts`** (new, pure): constants `TILT_Z = 2.5`, `FIRM_N = 60`, `MIN_N = 10`;
   bucket keys; `gameBucket(n)`, `streakBucket(run)`;
   `tiltCounts(sessions: { matches: TiltMatch[]; ended: boolean }[], counts: (m) => boolean)` →
   `{ counts: TiltCounts; noResult: number }` where `TiltCounts = { games: WL[4], streaks: WL[4],
   sessions, endedOnLoss }` (the sent shape; `noResult` is log-only). Reuse `WL` from `shared/clutch.ts`;
   `wilson(w, n)`, `tiltBuckets(counts)` → per-bucket `{ key, w, n, rate, lo, hi, z, restRate }`;
   `tiltVerdict(buckets, totalN, totalW)` → `{ state, key | null, … }` (no prose). Lifted from the
   prototype's `build` / `bucketsOf` / `verdictOf` unchanged in behaviour.
2. **Server** `src/server/api/pages.ts`: return `byGuid` from `index()` (today a local at `:36`; don't
   reuse `rowsOf`, it applies the page filters). In `period()`, add `tilt: tilt(idx, inRange, wanted)`.
   Walk `idx.all` sessions; per session take guids → `byGuid` rows that are `played` and
   `inFilter(_, "everything")`, in the cut's order; keep sessions with such a row in range; `ended` =
   session isn't `idx.current`. Feed `tiltCounts` with
   `counts = (r) => inRange(r) && wanted(r) && clutchCounts(r.playlistId)`. No new reads. Null when no match lands. Log `logger.info(C, "tilt",
   { matches, sessions, endedOnLoss, noResult })` — answers: how many landed, how many sessions, how many
   result-less matches were skipped from streaks.
3. **Schema** `src/shared/schemas/responses.ts`: `tiltSchema` (`games`/`streaks` as 4-tuples of
   `record`, `sessions`, `endedOnLoss`) `satisfies z.ZodType<TiltCounts>`; `periodResponse.tilt:
   tiltSchema.nullable()`; export `TiltView`.
4. **Web logic** `src/web/logic/tilt.ts`: axis labels, phrases, verdict text, bar tone/thin/focus per
   bucket (moved out of the prototype's inline `Columns` code), which legend rows show, the note text.
   Reuses `shared/tilt.ts` for the maths. `Tilt.tsx` holds no logic of its own.
5. **UI** `src/web/pages/trends/Tilt.tsx` + `Tilt.module.css`: the prototype's `Chart` / `Columns` /
   `Legend`, minus the variant switcher and demo slides; CSS from `prototype-tilt.module.css` minus
   `.bar`/`.demo`. Mounted in `TrendsPage.tsx` after `<Clutch>`. Run `ui-implementation-guidelines`
   (and `dataviz` for the chart marks) during the build; keep the approved look. Accessibility: each
   column's % and count readable (visually-hidden "N won of M" like Clutch's `recordLabel`), whiskers
   `aria-hidden`.
6. **Rules registry** `src/server/rules/registry.ts`: read rules `tilt_session_order` (game number and
   streak over every played match of the session; no-result matches keep the number, skip the streak;
   buckets; private/offline left out) and `tilt_verdict` (constants `TILT_Z`, `FIRM_N`, `MIN_N`; the
   four states), refs `ANALYTICS_MAP`; pins in `constant-pins.json`; `bun run definitions`.
7. **Docs**: map row B → Done (keep the verdict text, correct "under 30 matches" → "under 60", say
   "every match in the session (private and offline left out)", add "Plan: docs/plans/2026-11-24-tilt.md"),
   `PROJECT_INDEX.md` entries for the new files, BACKLOG diff as already staged in the working tree.
