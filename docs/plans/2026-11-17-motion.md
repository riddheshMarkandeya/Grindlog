# Motion build for the web dashboard

Tier: **Substantial** (new shared pieces, a routing mechanism, about 400–600 lines over 8 steps). Repo
copy: `docs/plans/2026-11-17-motion.md` (step 0).

## Context

The user asked for small motion additions, not an overhaul. The research note
`docs/research/2026-11-17-ui-motion.md` and a prototype on branch `prototype/motion` (`4f282cc`,
reference only, never merged) settled the details. The note's **"Prototype verdict"** section is the
spec. `docs/research/2026-11-17-route-view-transitions.md` ranks the page-transition mechanisms; this
plan uses option 1.

User decisions (fixed):
- Mostly calm motion. Springs only on selection changes. No number count-ups.
- **Charts:** draw in once per page load, then move between old and new values on later data changes.
- **Press:** `scale: .97` on `:active`.
- **Dialog:** fade + 8px rise.
- **Selection indicator:** one sliding element per group, on the bouncy spring. Groups: the header
  nav, the Recap Overview / Matches & numbers tabs, the match rail (vertical), and the By date / By
  match toggle.
- **Page transitions:** only `<main>` animates. Route (path) changes **rise**; filter (search-only)
  changes **crossfade**. `useTransitions={false}` stays (`src/web/main.tsx:22`).
- **Timeouts rejected:** a delay moves the race gap, it doesn't close it. The `window.location`
  redirect check closes it (the BACKLOG "redirect is pending" item, `BACKLOG.md:185-191`).
- **New in this request:** "similar transition effects in the settings page elements where they make
  sense" (step 7).

## Motion tokens (`tokens.css` `:root`; exact values)

From the research note:
```
--dur-1:100ms --dur-2:150ms --dur-3:250ms --dur-exit:150ms
--ease-standard:cubic-bezier(.2,0,0,1) --ease-enter:cubic-bezier(0,0,0,1) --ease-exit:cubic-bezier(.3,0,1,1)
--ease-spring: linear(0,.049,.161,.295,.43,.553,.659,.746,.815,.868,.909,.938,.96,.975,.985,.992,.996,.999,1)  --dur-spring:320ms
--ease-spring-bouncy: linear(0,.052,.17,.316,.463,.597,.712,.804,.875,.927,.963,.987,1.002,1.011,1.014,1.015,1.014,1.012,1.01,1.008,1.006,1.004,1.003,1.002,1)  --dur-spring-bouncy:430ms
```
Added for this build:
- `--dur-rise-out: 90ms` and `--delay-rise: 60ms`: the page rise.
- `--dur-draw: 600ms` and `--delay-dots: 350ms`: the chart draw.
- `--dur-tween: 320ms`: the W/L bar `d` morph. It matches the JS line tween.
- `--dur-pulse: 1s` and `--dur-status: 2.3s`: the existing `Loading` and `SaveStatus` animations,
  moved to tokens.
- Spatial: `--press: .97` and `--rise: 8px`.

## Reduced motion: done by tokens, not a kill-all

WCAG 2.3.3 doesn't count colour or opacity as motion, so `global.css:42-43`'s `* { transition:none;
animation:none }` goes. In its place, `tokens.css` gets:
```
@media (prefers-reduced-motion: reduce) { :root { --press: 1; --rise: 0px; --dur-spring: 0ms; --dur-spring-bouncy: 0ms; --dur-tween: 0ms; } }
```
- Every spatial effect reads one of these tokens: press, dialog rise, page rise, indicators, the
  switch thumb, the bar morph.
- The result under reduce: fades stay, and everything spatial jumps.
- What needs its own reduce line:
  - Chart draw-in: `animation: none`.
  - The line tween (JS): checks `matchMedia`.
  - `Loading`'s infinite pulse: `animation: none`. `SaveStatus` already has its line.
- A vitest guard keeps this true. It extends `src/web/styles/tokens.test.ts`, which already globs
  every CSS file.
  - **No exceptions:** no CSS file outside `tokens.css` may put a raw duration (`\d*\.?\d+m?s`) in a
    `transition`, `transition-duration`, `transition-delay`, `animation`, `animation-duration` or
    `animation-delay`.
  - The reduce block must set the five spatial tokens.

### 4. Sliding selection indicator
- **The hook:** add `src/web/components/useIndicator.ts`, signature
  `useIndicator(ref, activeSelector, axis: "x" | "y", activeKey)`.
  - In a layout effect, keyed on `activeKey`, it measures the active child's
    `offsetLeft`/`offsetWidth` (or `offsetTop`/`offsetHeight`).
  - It writes `--ind-pos` and `--ind-size` on the container.
  - It re-measures from a `ResizeObserver` on the container, for font load, wrapping and the
    sidebar.
  - **States** (`data-ind`):
    - `placed`: the first measure, with no transition, so nothing slides in from 0 on mount.
    - `live`: set one frame later. Only `live` carries the transition.
    - `none`: no active child. The indicator fades out (opacity, `--dur-2`).
  - **Coming back from `none`:** go through `placed` → `live` again. The indicator appears at the
    new item and fades in rather than sliding from its stale spot.
  - **`none` is expected in two cases:** the header on Settings, whose link sits outside `.topnav`
    (`Header.tsx:24-33`), and the rail with no match open. So there's no log for it, because it
    would be noise. A miswired selector shows in the e2e below instead.
- **The CSS:** each module draws the indicator as `::after`.
  - `position: absolute; translate: var(--ind-pos) 0; width: var(--ind-size)` (`y` axis:
    `translate: 0 var(--ind-pos); height: var(--ind-size)`).
  - Under `[data-ind="live"]`: `transition: translate var(--dur-spring-bouncy)
    var(--ease-spring-bouncy), width/height (same), opacity var(--dur-2)`.
  - The container gets `isolation: isolate`, and the indicator `z-index: -1`.
  - **Positioning:** add `position: relative` only where the container isn't positioned yet. The
    rail is already `position: sticky` (`MatchView.module.css:11`); sticky counts as positioned and
    must not be overridden.
  - The old per-item highlight (border, background) is dropped only under `[data-ind="placed"]` and
    `[data-ind="live"]`. Before the first measure, the static highlight still shows.
  - Animating `width` on one small absolute element is accepted, as in the prototype.
- **Groups (6):** the four from the verdict, plus two of the same kind:

  | Group | Where | Active | Shape |
  |---|---|---|---|
  | Header nav | `Header.tsx` `.topnav` | `[aria-current="page"]` | 2px line, bottom |
  | Recap tabs | `RecapPage.tsx:192` `.tabs` | `[aria-current]` | line over the nav's border (`bottom: -1px`) |
  | Match rail | `MatchView.tsx:52` `.rail` | `[aria-current="page"]` | vertical row: `surf2` + inset 3px accent |
  | X axis | `TrendChart.tsx:69` `.xmode` | `[aria-pressed="true"]` | accent pill |
  | Settings segments | `SettingsPage.tsx` `Choice` (not swatches) | `label:has(:checked)` | accent pill |

  - Settings segments and ModeSwitch are added because they are the same segmented control as X
    axis. Leaving them instant would make the app inconsistent. Both change local state only, not
    the URL, so a page transition never captures their slide.
  - Text colour on pill items transitions at `--dur-2`.
- **Tests (live UI, `tdd-live-code-carveout`, e2e repro first, red before the hook exists):**

- **Pure logic, TDD:** `tweenPoints(from, to, k)` in `src/web/logic/trend-chart.ts`.
  - The output always has `to`'s length.
  - Index-mapped lerp.
  - A point with no `from` counterpart starts from `from`'s last point, or from itself when `from`
    is empty.
  - `k` is clamped to [0,1].
  - Tests in `trend-chart.test.ts`: same length, growing, shrinking, empty from, k=0/1.
- **The hook:** `useTweenedPoints` (rAF, `--dur-tween`'s 320ms, easeOutCubic) lives beside
  `TrendChart`.
  - Under reduced motion it returns the target at once.
  - It works on point arrays, not path strings.
  - A new target mid-tween starts from the points currently shown.
- **Draw once:**
  - A module-level `drawn` set (`trend`, `winloss`) is marked in an effect after the first chart
    mount, never during render, so StrictMode's double render can't skip it.
  - That render carries the draw classes:
    - Line: `pathLength=1`, `stroke-dasharray`/`dashoffset` keyframe, `--dur-draw`.
    - Dots: fade, `--delay-dots`.
    - W/L bars: `scale: 1 0` from the midline, using `transform-origin` bottom for wins and top for
      losses, with `transform-box: fill-box`.
  - **Switching from draw to tween:** on `animationend` of the line (the bars, for the W/L chart),

  - Later changes: line and dots tween. Bars are keyed by index and morph
    `d` (`transition: d var(--dur-tween) var(--ease-standard)`; Chromium only, a plain swap

- **Tests:** `test/e2e/trends.spec.ts`.

### 6. Page transitions and the redirect guard
- **Pure logic, TDD:** add `src/web/logic/page-transition.ts`:
  - `transitionStyle(prev, next, type)` returns `"rise" | "crossfade" | null`.
    - Different pathname: `rise`.
    - Same pathname, different search: `crossfade`.
    - Otherwise (state or hash only): `null`.
    - `REPLACE` is also `null`: a redirect isn't a page change the user made, and the start-up chain
      `/` → `/recap` → session doesn't stack transitions.
    - Accepted cost: FriendPage's remove (a replace to `/friends`) cuts to the list without a rise.
  - `shouldRedirect(rendered, current)`: pathname+search equality. Paths are already
    `encodeURIComponent`-built, so string comparison with `window.location` is safe.
  - Unit tests for both.
- **The hook:** add `src/web/usePageTransition.ts`, `useShownLocation()`.
  - It keeps `{location, navigationType}` in state, and a `latest` ref updated on every router
    location change.
  - On a change, it either sets the state at once (no `document.startViewTransition`, or a null
    style) or:
    - sets `document.documentElement.dataset.vt = style`;
    - calls `document.startViewTransition(() => flushSync(() => set(latest.current)))`.
    
    Reading the ref, not a captured value, means a transition's late callback can't put back a
    location older than the URL.
  - Errors:
    - `ready` rejects with `AbortError` when a newer navigation skips this one. That is expected and
      swallowed, with a comment saying why.
    - `updateCallbackDone` rejecting means the render inside it threw. It logs
      `console.warn("[grindlog] page/transition_failed", {to, error})`.
  - `console.debug("[grindlog] page/transition", {style, from, to})` on each start.
- **`App.tsx`:**
  - Render `<UNSAFE_LocationContext.Provider value={shown}><Routes>…</Routes></Provider>`.
  - **Why not `<Routes location={shown}>` as in the prototype:** that form hard-codes
    `navigationType: "POP"` for everything inside (`react-router/.../lib/hooks.js:616-627`). That
    breaks `RecapSession`'s focus rules: `RecapPage.tsx:151` (`pushed = navigation !== Pop`) would
    stop returning focus to the filter select after a filter change.
  - The provider keeps the real type. `<Routes>` reads its location from that context. The value has
    the Router's own `{location, navigationType}` shape (`components.js:569-578`). The export exists
    in 8.4 (`index.js:45`).
  - Fallback if the UNSAFE export misbehaves: keep `<Routes location>` and pass the type through a
    small app context read by `RecapPage`.
  - The Header stays outside the provider, so it sees the real location at once and its indicator
    starts sliding immediately.
- **CSS, in `global.css`:**
  - `main { view-transition-name: page }`.
  - **Live groups during a transition:** only the indicator groups inside `main` that can survive a
    navigation keep their slide live: Recap tabs, the match rail and X axis (the verdict's set). They
    get `view-transition-name: match-element; view-transition-class: keep`.
    - Settings segments and ModeSwitch never slide during a navigation, so they're left out. A `keep`
      on them would show them instantly while the rest of a new page fades in.
  - Root: the old image is hidden and the new one isn't animated.
  - `keep` groups: no animation, and the old image is hidden.
  - `html[data-vt=rise]`: the old page fades out (`--dur-rise-out --ease-exit`). The new one fades in
    rising from `var(--rise)` (`--dur-3 --ease-enter`, delayed `--delay-rise`).
  - `html[data-vt=crossfade]`: old out `--dur-exit`, new in `--dur-3`.
  - Under reduce, the rise becomes a fade through `--rise: 0px`. Opacity is kept, as Chrome's
    guidance allows.
- **Clicks during a transition:** check in Chrome first. The spec routes hit testing to the document
  element while a transition runs (`route-view-transitions.md:48`), so a quick second header click
  might be lost.
  - If it is, add `::view-transition { pointer-events: none }` so clicks fall through to the live
    page, and re-check.
  - Either way, an e2e in `shell.spec.ts` covers it. It clicks Trends, then Friends within 150ms, with
    `force: true` so Playwright's actionability retry can't hide a swallowed click, and asserts the
    URL and the page are Friends.
  - If neither fix works, that is a stop-and-ask point: shorten the rise, or drop it for header
    clicks.
- **The redirect guard** (the BACKLOG item; closes it). Add `src/web/redirect.ts`:
  - `redirect(navigate, to, rendered, opts)`: when `shouldRedirect(rendered, window.location)` is
    false, it logs `console.info("[grindlog] redirect/skipped", {to, rendered, at})` and returns.
    Otherwise it does `navigate(to, {replace: true, ...opts})`.
  - A `<Redirect to>` component (effect + `useLocation` + the helper) replaces `<Navigate replace>`.
- **The redirect sites:** `App.tsx:48` (`/`), `RecapPage.tsx:82` and `:84` (`<Redirect>`),
  `RecapPage.tsx:132`, `TrendsPage.tsx:69`, and `FriendPage.tsx:147` (mutation `onSuccess`: the user
  may have left during the request).
  - Also `FriendsPage.tsx:50`: a same-path state-clearing replace in an effect, the same class of bug.
  - `rendered` is the page's own `useLocation()`: the shown location the decision was made on.
- **Tests:**
  - Unit tests for the pure parts.
  - The e2e for the skip path, since vitest has no DOM:
    - in `friends-page.spec.ts`, stub the remove request slow;
    - click Remove → confirm;
    - navigate to Trends before it resolves;
    - assert the URL stays on Trends and the console shows `redirect/skipped`.
  - The interrupt path: the double-click e2e above (two transitions, the second skips the first; the
    end state must be the second).
  - Race: the shell spec at 30×.
