# Installer and self-update tooling for Grindlog (2026-11-06)

Feeds: map tickets "Updater design" and "Release workflow". "Source says" = a fetched primary page; "Inference" = my reasoning. Several pages were read through a summarising fetch tool, so exact wording is not guaranteed.

## Recommendation (inference from the table below)

**Inno Setup (per-user installer) plus a small hand-written updater inside the supervisor.**
- Inno is the only candidate where every installer requirement is documented or plainly supported: per-user, no admin, ARP entry, Start menu, and a scripted uninstall prompt. It is free for any use.
- The updater is about 100-150 lines of Bun: poll GitHub, download the new `Setup.exe`, verify it, wait for the game to close, run it silently, and check health afterwards. Rollback is the part we write ourselves.
- Velopack is the runner-up, and the right pick if delta updates and built-in apply/rollback matter more than the uninstall prompt. Its docs do not describe rollback, and its hooks cannot show UI (see below). Verify rollback in a throwaway spike before choosing it.
- Rule out MSIX (unsigned) and WiX/MSI (fee terms, no self-update). NSIS works but offers nothing over Inno here.

## GitHub Releases as update source

- `GET /repos/{o}/{r}/releases/latest` returns "the most recent non-prerelease, non-draft release", sorted by `created_at`, which is the commit date, not the publish date. [docs](https://docs.github.com/en/rest/releases/releases#get-the-latest-release). So prereleases and drafts are ignored for free. Inference: a release created from an older commit but published later can lose to an earlier-created one, so do not backdate releases or tag out of order.
- Unauthenticated limit: 60 requests/hour per originating IP. [docs](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api). Inference: many users behind one NAT share that budget, so poll about every 6-24 hours with jitter.
- ETag: send `If-None-Match` with the saved `etag` and get `304`. The source says a 304 "does not count against your primary rate limit" if the request includes a valid `Authorization` header. [best practices](https://docs.github.com/en/rest/using-the-rest-api/best-practices-for-using-the-rest-api). Inference: anonymous 304s are probably counted, but this is not documented. ETags still save bandwidth. Honour `x-poll-interval` if sent.
- Velopack's own GithubSource has a `prerelease` flag that defaults to false in the Python reference. [ref](https://docs.velopack.io/reference/py/Sources/GithubSource). I did not find how it treats drafts, which are not visible to anonymous callers anyway (inference).

## Verifying an unsigned download

- **SHA-256 file in the same release:** detects corruption and truncated downloads only. It gives no protection if the release or account is compromised, because the attacker replaces both asset and hash. (Inference: they share a trust root.)
- **Detached minisign signature, public key baked into the app:** an Ed25519 signature. [minisign](https://jedisct1.github.io/minisign/). It protects against a compromised GitHub account or release tampering, provided the secret key is kept off GitHub; it also protects against a swapped CDN asset. It does not protect against a compromised signing key or a malicious build produced by our own CI if the key lives there. The trusted comment is covered by the signature, so it can carry the version and file name to block downgrade and replay. [minisign](https://jedisct1.github.io/minisign/).
- Costs and caveats: the page names only the C `minisign` CLI (libsodium) and no JS/Bun verifier library, though the format is simple enough to verify with `node:crypto` Ed25519 plus a Blake2b-512 prehash, which needs checking (inference; open question). Key rotation and loss need a plan. Neither option replaces Authenticode: Windows SmartScreen will still show warnings for unsigned binaries. [signing page](https://learn.microsoft.com/en-us/windows/msix/package/signing-package-overview) on reputation.
- Suggested: ship both (hash for corruption, minisign for authenticity). Key storage in CI is the open design choice; it is the only real security gain over SHA-256.

## Replacing a running exe on Windows

- No primary source fetched states the rename behaviour. From general Windows knowledge (unsourced, test it): a running exe cannot be overwritten or deleted, but it can be renamed; the usual technique is rename old to `.old`, write the new file, restart, and delete `.old` later. Another route is a separate process (updater or installer) that waits for the PID to exit, then swaps.
- `MoveFileEx` with `MOVEFILE_DELAY_UNTIL_REBOOT` defers a replace to reboot, but needs admin or LocalSystem. [docs](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexa). It is unusable for our no-admin requirement.
- Tool behaviour: Velopack's Update.exe waits on the app PID (`--waitPid`, up to 60 s) then replaces `current`. [manager.rs](https://docs.rs/crate/velopack/1.2.0/source/src/manager.rs), [overview](https://docs.velopack.io/integrating/overview). Inno's `CloseApplications` uses Restart Manager to close and restart apps holding files. [closeapps](https://jrsoftware.org/ishelp/topic_setup_closeapplications.htm). Since Grindlog's game-closed gate already exists, the supervisor can stop the tracker, run the installer silently, then restart (inference).

## Mark-of-the-Web on app-downloaded files

- The mark is an NTFS `Zone.Identifier` stream written by the downloading client, either via `IAttachmentExecute` (Chrome) or by writing the stream directly (Firefox). Microsoft's own page was not reachable; this comes from Eric Lawrence's posts, a secondary source: [downloads and MOTW](https://textslashplain.com/2016/04/04/downloads-and-the-mark-of-the-web), [additional guidance](https://textslashplain.com/2022/12/02/mark-of-the-web-additional-guidance).
- Inference: a Bun `fetch` + `writeFile` writes no stream, so the file has no MOTW and will not trigger the "Windows protected your PC" SmartScreen prompt on the silent run. A user's browser download of the first installer does get it, which is the unavoidable SmartScreen click for unsigned builds. Not tested here.
- Neither Velopack nor Inno docs read mention setting or clearing the mark (open; confirm by testing a downloaded installer with `Get-Item -Stream *`).
